# bookmarks

<img src="docs/icon.png" width="40" alt="">

一个同人文管理程序，同时也是本地离线的 AO3 书签页替代品。它这样即使作品在 AO3 上被隐藏或删除，也依然还在。

![界面](docs/screenshot.png)

## 它能做什么

**导入与归并。** 支持 PDF、HTML、EPUB、TXT 以及其他格式。同一作品的多个文件会归并成一条记录，所以一个既有 HTML 又有 EPUB 和 PDF 的故事只出现一次，带一个 `3 格式` 徽章，而不是出现三次。

**自动配对译文。** AO3 会标明哪些作品是哪些的译文，所以原文和译文不需要任何手动操作就能关联起来——即使你隔了几个月才导入另一个。它们在列表里保持相邻，译文排在原文下面。

**保留多个版本。** 连载作品会更新，完结作品也可能修订后重发。两份都会保留，其中一份标记为当前版本，你可以切回旧版或删掉任意一份。内容完全相同的文件绝不会存两份。

**模糊搜索。** 搜索覆盖标题、作者、你自己的标签、AO3 标签、你的备注和摘要。标点和大小写会被折叠，所以 `一二三` 能找到 `一，二，三`。可以按标签或语言筛选，按日期、字数或标题排序，按译文、系列或不分组来排列。

**记录详细信息。** 标题、作者、摘要、发布与完成日期、字数和语言，再加上你自己的备注和标签。日期接受 `2019`、`2019-06` 或 `2019-06-09`，并记住你给到的精度。凡是估算的值都带 `~` 标记，所以估算绝不会被当成确切数据；而你自己输入的数字，之后的导入也不会覆盖它。

**维护系列。** 作品可以属于某个系列并带有序号；系列和译文关联是分开记录的，因为一个系列里可以有译文。

**记录你没能下载的作品。** 如果作品已经消失，可以手动添加，填上标题、作者和你还记得的信息。

## 你的书库在哪里

所有东西都在你的磁盘上：一个 SQLite 数据库，加上存放实际文件的 `library/` 目录。不会上传到任何地方，也不需要账号。

设置文件在 `%APPDATA%\com.bookmarks.app\settings.json`。书库本身默认在 `%USERPROFILE%\Documents\bookmarks`，可以在设置面板里改到任何位置——比如系统盘快满时换一块盘。移动过程是 复制 → 校验 → 切换 → 删除，所以中途中断时书库会留在原处。

备份就是复制这一个文件夹。工具栏里有按钮可以直接打开它。

## 安装

从 [Releases](../../releases) 下载 `bookmarks_0.1.0_x64-setup.exe`（安装程序）或 `.msi`。构建未做代码签名，所以首次运行时 Windows SmartScreen 会警告——选「更多信息」→「仍要运行」。

## 从源码构建

需要 Node、Rust 工具链，以及 WebView2 运行时（Windows 11 已自带）。

```
npm install
npm run app:dev          # 开发：热重载
npm run app:build        # 发布：.exe + 安装包
```

`cargo test` 跑 Rust 测试集，`npm run typecheck` 检查界面类型。

## 说明与限制

- **整个书库在加载时读入内存。** 这让筛选和排序是即时的，在这个量级下是合适的取舍，但它不是为几万篇作品设计的。
- **不提取 EPUB 和 PDF 的文本**，所以这些文件不产生可搜索文本，字数必须手动输入。PDF 是刻意如此：扫描件的 PDF 需要 OCR 才有意义。
- **归并依据证据。** 首先用 AO3 作品 id，其次是文件名与标题匹配。什么都不匹配的文件会成为独立记录，而不是靠猜合并——错误合并会破坏已有记录，而多出的一条记录只需点一下就能合并。
- **还没有 CSV 导入**，所以不能直接读取 AO3 的书签导出文件。
- 界面是中英双语，但应用本身没有做多语言翻译。
